# 会话文本清理（插件版）

> 五个工具：`detox_find`（按名字找会话）、`detox_scan`（只读）、`detox_cut`（剪会话文件）、`detox_blocks`（清压缩块摘要）、`detox_workspace`（扫工作区）。
> 零依赖，不需要 python，不需要外部脚本。

## 什么时候用

- 某条会话的思考里「极短重复行」越写越多，清了过一阵又长回来
- 压缩摘要里还挂着大段这样的行（每轮注入，等于反复提醒）
- 用户说「清一下」「剪掉那些重复行」「压缩块里还留着」

## 五个工具：输入什么，返回什么

**所有 `session` 参数都吃「id 或前 8 位前缀」**，例如 `989d9c6b` 或完整的 `989d9c6b-4f1f-4a04-ad21-4b2153eb6eb3`。**不要传会话名**——名字先用 `detox_find` 换成 id。

---

### 1. `detox_find` —— 名字 → id（先跑它）

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `query` | string | 否 | 会话名关键词（子串、不分大小写），也可以是 id 前缀。**不传就列出最活跃的若干条** |
| `limit` | number | 否 | 最多返回几条，默认 10，上限 50 |

**返回**：

```json
{
  "query": "11号",
  "total": 1,
  "sessions": [
    { "id": "989d9c6b-4f1f-4a04-...", "host": "11号涩涩大肥鱼",
      "title": "大肥鱼，你是一个……", "sizeBytes": 2199502, "idleSec": 106, "inDb": true }
  ]
}
```

字段怎么读：

- `id` —— 后面三个工具要传的就是它（前 8 位就够）
- `host` —— 那条鱼的名字（会话标题栏那行）
- `title` —— 第一条用户消息的开头
- `idleSec` —— **最后一次写盘距今多少秒**。`< 180` 表示她还在跑，`detox_cut` 会拒绝
- `inDb` —— `true` 说明标题来自 billion-context 账本，`false` 说明是从会话文件头硬解出来的

关键词太宽（例如只给一个数字）时，命中 `host` 的排最前，同组按最近活跃排序。

---

### 2. `detox_scan` —— 只读，先看量

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `session` | string | **是** | 会话 id 或前 8 位前缀 |

**返回**：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `session` / `file` | 完整 id 与文件路径 | 记下来，后面还要用 |
| `mtimeAgeSec` | 最后一次写盘距今秒数 | 和 180 比 |
| `writable` | `mtimeAgeSec >= 180` | **`false` 时别跑 cut**，会被拒 |
| `events` | 会话里的事件总数 | 分母 |
| `touched` | 会被改的事件条数 | 和 `events` 比，看占比 |
| `stubs` | 会删掉的极短行数 | 绝对量，越大越值得切 |
| `loops` | 会删掉的连写循环段数 | 通常是 0 |
| `chars` | 会删掉多少字符 | 体积能降多少 |
| `blocksTotal` | 压缩块总块数 | 0 或报「没找到账本」＝ 压缩块这项用不上 |
| `blocksHit` | 有残留的块 id 列表 | 非空才需要 `detox_blocks` |

**典型判读**：`touched` 几百条、`stubs` 上千 → 值得切；`touched` 个位数 → 不用切，或者只清压缩块。

---

### 3. `detox_cut` —— 剪会话文件（唯一会改会话文件的）

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `session` | string | **是** | 会话 id 或前 8 位前缀 |
| `force` | boolean | 否 | 跳过 180 秒空闲检查。**默认不要用**，只在确认会话已停仍报忙时开 |

**返回**：

| 字段 | 含义 |
|---|---|
| `backup` | 备份文件完整路径（`~/.dsh/detox-backups/orig-<id前8位>-<时间戳>.v4.jsonl.zstd`） |
| `events` | 处理的事件数 |
| `touched` | 实际改了的事件条数 |
| `stubs` / `loops` / `chars` | 实际删掉的极短行 / 循环段 / 字符数 |
| `bytesAfter` | 覆盖后文件体积 |
| `removedCache` | 是否顺手删了投影缓存（正常都应删） |

**做完会自己回读校验**：解包后逐字节比对（除改动处）、查 seq 空洞、查缺 role。任何一项不过就**不覆盖**，原文件保持不动。

跑完再 `detox_scan` 一次，`touched` 必须是 0。

---

### 4. `detox_blocks` —— 清压缩块摘要（唯一必须重启的）

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `session` | string | **是** | 会话 id 或前 8 位前缀 |

**返回**：

| 字段 | 含义 |
|---|---|
| `backup` | 整库备份路径（`index.db.bak-<时间戳>`，约 800MB，记得留磁盘） |
| `changed` | 改了几块 |
| `details[]` | 每块 `{ id, before, after }` 字符数 |

**只改 `blocks.payload_json` 里的 `summary` 字段**，`content` 表里的全文一个字不动。

---

### 5. `detox_workspace` —— 扫工作区（只报告，不改）

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `root` | string | 否 | 工作区根目录；省略＝进程当前目录 |

**返回**：

```json
{ "root": "H:/大肥鱼的工作室", "scanned": 118, "total": 3,
  "files": [ { "path": "AGENTS.md", "kind": "agents", "hits": [ { "line": 52, "label": "…", "snippet": "…" } ] } ] }
```

- `scanned` —— 扫了几个「会被注入上下文」的文件
- `total` —— 一共几处可疑
- `files[].hits[].line` —— 行号，直接拿去看那一行

**它只提示位置，不改文件**：文档里的内容是给人看的，删不删要人判断。

---

### 常见报错怎么处理

| 报错原文 | 原因 | 怎么办 |
|---|---|---|
| `找不到会话 "xxx"` | 传的是名字不是 id，或者 id 打错了 | 先 `detox_find{query:"xxx"}` |
| `还在写（mtime N 秒前，判据 180 秒）` | 会话正在跑 | 等她停下来；等不了就让用户停掉；`force` 只在你确认已经停了但 mtime 还新时用 |
| `前缀 "xxx" 匹配到 N 个会话` | 前缀太短 | 给长一点，12 位基本够 |
| `没找到账本，可能是别的压缩插件` | 没装 billion-context，或换了压缩后端 | 压缩块这一项跳过；会话文件那刀照样能跑 |

## 先找会话（别硬猜 id）

用户只会说名字（「帮 11 号去毒」「那条 P站小说的会话」），不会给 uuid。

1. `detox_find{query:"11号"}` —— 标题和 host 都是现成的，从 bili 账本的 `sessions` 表读，一条 SQL 就够。
2. 命中行里取**前 8 位 id**，再看「空闲多少秒」：`< 180s` 说明还在写，别急着 cut。
3. 关键词太宽（例如只给一个数字）时按 host 命中优先排序，最近的在前。

账本里没标题的会话，`detox_find` 会退回读文件开头几帧的首条用户消息，仍然给得出名字。

## 顺序（不能换）

0. **`detox_find`** —— 拿到 id。跳过这步直接猜前缀，十有八九白跑。
1. **`detox_scan`** —— 先看量。它报：事件数、待改条数、极短行数、循环段数、以及压缩块里哪几块有残留。
2. **`detox_cut`** —— 剪会话文件。**这一步不用停 DSH**：它自己查 mtime，不足 180 秒直接拒绝（运行中的会话写断 seq 会打不开）；切完文件已落盘、投影缓存已删，下次打开读到的就是清理后的内容。
3. **停掉 DSH** —— 只有要走第 4 步才需要停。
4. **`detox_blocks`** —— 剪压缩块摘要，改前整库备份约 800MB。
5. **重启 DSH** —— 清过压缩块就必须重启（不重启，bili 进程内存里的整份 payload 会把磁盘改回去）；然后 `detox_scan` 复查：待改必须是 0，压缩块必须无残留。

> **只动了会话文件、没碰压缩块 → 不用重启。** 重启的唯一理由是压缩块。

## 三条硬规矩

1. **会话在写时不动刀**。`detox_cut` 会拒，`force: true` 只在明确知道会话已停但仍报忙时用。
2. **剪压缩块必须重启**。不重启等于白改，几十秒到几分钟内会被盖回去。
3. **`user/message` 一个字都不动**，`tool-call` 的 `arguments` 也不动。工具已经按这个写死，不要绕过它手改文件。

## 给自己清理：派一个子智能体

会话正开着时自己的 mtime 永远是 0 秒，`detox_cut` 直接拒绝。**但子智能体能切**——这是实测出来的：

> 主会话在「等子智能体结果」的这段时间里**不产生新事件**，mtime 就会一路涨。实测 4 轮扫描：1 秒 → 58 秒 → 122 秒 → 190 秒，第 4 轮变成「可动」，cut 一次成功，没用 force。

### 任务书模板（直接抄，替换 id）

```
你是执行者，禁止再派子智能体，直接干完回报。

目标会话 XXXXXXXX。它现在开着，所以 mtime 是 0 秒，直接切会被拒。
但主会话在等你的结果时不产生新事件，你等够 180 秒它就会变成可动。

1. detox_scan{session:"XXXXXXXX"}，记下 mtime 几秒
2. mtime < 180 就用 bash 跑 sleep 60 等一轮，再扫一次；最多 5 轮，每轮都记数字
3. 关键观察：mtime 在涨吗？每轮都还是 0~5 秒说明主会话在写东西 → 立刻停手回报，别硬切
4. 看到 mtime ≥ 180 → detox_cut{session:"XXXXXXXX"}，不许传 force
5. 切完 detox_scan 复查。主会话可能又写了新事件，剩几条属正常

禁止：force、用别的工具改文件、读那条会话的内容（读进来可能影响你自己）、猜数字。
```

### 主会话这边必须做到一件事

**闭嘴。** 等待期间一个字都别说、一个工具都别调——每说一句就写一条事件，mtime 归零重来。我第一次试的时候没忍住说了两句话，结果白等一轮。

### 什么时候别试

- 子智能体那边每轮扫描都显示 mtime 个位数 → 说明有东西在定期写事件，这条路不通，老老实实停下来让用户开新会话切。
- 会话正在被用户手动操作 → 别切。

## 判据：先分清楚哪条认字、哪条不认字

`lib/detect.js` 顶部四个正则，性质完全不同：

| 判据 | 怎么认 | 换条鱼还灵吗 |
|---|---|---|
| `STUB_LINE` 极短行 | **只按字数**：1~3 个汉字、可选句号、独占一行 | **灵**。别人写的是别的字照样抓得到 |
| `LOOP` 连写循环 | 任意汉字 + 句号连写 3 次以上 | **灵**。同样不认字 |
| `BAD_SECT` 小节标题 | 按词：某个固定的标题写法 | **不灵**。同源会话留下的 |
| `BAD_LINE` 点名行 | 按词：某句固定的说法 | **不灵**。同源会话的叫法 |

**所以：主判据（极短行、循环段）对别的会话一样有效，因为它们认的是形态不是字。**

**1~3 个字独占一行，在思考里不可能是正经内容**——它既没说对什么做、也没说做到哪一步；连「好的。」「收到。」这种应答都没有任何使用场景。**删它不是误伤。**

**真正要小心的是放宽到 4~5 字**：那时会开始碰到正常短句（「这里要改两处。」就是 6 个字，换成 4 字就危险了）。要放宽就一格一格试，每格跑一遍 `detox_scan` 看数字跳多少。

**两条按词的判据抓不到不代表干净**——别处多半不叫这个名字，补词即可，或者干脆不用它们、只看前两条。

**千万别改成「含某个词就删整句」**——旧版这么干过，把正常的一句用户要求整条删了。

## 压缩摘要存在谁手里

要清两样：会话文件里的文本、**以及每轮都会注入的压缩摘要**。后者存哪取决于装了哪个压缩插件：

| 插件 | 摘要存在哪 | 谁来清 |
|---|---|---|
| billion-context（bili） | 自己的 `index.db`（`blocks` 表） | `detox_blocks` |
| 官方 `dsh-compaction-basic` | 会话文件里的 `compaction/summary` 事件 | `detox_cut` |
| 多数第三方后端（vcc / instant / pro / better-compact …） | 仍然写 `compaction/summary` | `detox_cut` |
| 自建存储的（如 compaction-tower） | 自己的库或文件 | **要自己加读取器** |

**看到 `detox_scan` 报「没找到账本」或「共 0 块」，不等于干净**——很可能是压缩插件换了存储方式。这时去看那个插件的源码，照着 `lib/blocks.js` 写一份对应的 `scanBlocks` / `cutBlocks`。

**遇到不认识的压缩块，别信那个 0。**

## 备份

都在 `~/.dsh/detox-backups/`：`orig-<id前8位>-<时间戳>.v4.jsonl.zstd` 与 `index.db.bak-<时间戳>`。

## 清理的边界

**清理旧文本只能把存量降下来。** 上下文里这类行越提越多、越清越长时，最干净的做法是**换一条新会话**：把要留着的东西写进文件，新开一条，别在老历史里反复处理这件事。

一句话：**存量大就清，反复长就换。** 别在同一段历史里反复纠缠。
